Where agents
get stuck today.

We test your site the way each reader meets it: Googlebot, AI crawlers that fetch raw HTML, browser agents that click, and API agents that call tools. You get a score per layer and the fixes that move it.

  • Every reader tested

    The same pages fetched as Googlebot, an AI crawler, a browser agent and an API agent.

  • Each layer checked

    Access, rendering, Markdown, schema, protocols and actions, one by one.

  • Fixes in order

    What to build first, ranked by what it unlocks for buyers and agents.

Rendered for
every reader.

The major AI crawlers fetch your raw HTML without running JavaScript. If pricing, features or docs only appear after scripts load, they see an empty shell. We move key templates to server or static rendering and keep the interactive UI for people.

  • Raw HTML vs rendered

    What each crawler sees on every key template, side by side.

  • The right mode per template

    Server, static or hybrid rendering, built in the stack you already run.

  • Text first, interactivity after

    Interactive parts load on top of the text, never instead of it.

One URL,
two formats.

When an AI agent asks for a page, it gets clean Markdown: the content without layout or scripts, so it reads and quotes you accurately. A person on the same URL still gets your full design.

  • Content negotiation

    Agents that ask for Markdown get Markdown. Browsers get HTML. Same URL.

  • llms.txt and Markdown copies

    A map of your key pages for AI tools, plus a .md copy of each.

  • Parity check

    Both formats carry the same facts on every release. Never a separate version for bots.

Speak the
agent protocols.

Agents don't only read pages. They call tools. We build these endpoints for you, or spec them for your team, each scoped to exactly what you choose to expose.

  • MCP server

    Lets assistants like ChatGPT and Claude search your docs, pricing and integrations.

  • WebMCP tools

    Page actions like book_demo that browser agents can call. A proposed standard, in a Chrome trial.

  • A2A and NLWeb

    An agent card other agents can read, and a plain-language endpoint over your content.

Pages agents
can operate.

Browser agents read your page much like a screen reader does: through labels, roles and structure. Unlabelled buttons and div-only forms stop them. We make every key action clear to agents and to people.

  • Accessibility tree audit

    Every button, link and field checked for a name, role and state.

  • Forms agents can finish

    Labelled fields, clear errors, and no hover-only menus or hidden steps.

  • Tested with real agents

    We run browser agents through your demo and trial flows, before and after.

what you are.

Structured data tells agents and AI engines exactly what your company and product are. We write one connected JSON-LD graph into your server HTML, tie it to your profiles, and tell engines when it changes.

  • One graph, server-rendered

    Company, product, articles and FAQs in the first HTML response, linked by @id.

  • One connected entity

  • Freshness signals

Decide who gets
in, and why.

Not every bot wants the same thing. Some train models, some answer searches, some fetch a page because a person asked. We set a policy per purpose and keep the crawlers behind AI answers open.

  • A policy per purpose

    Training, search and user-triggered fetches, each allowed or blocked on purpose.

  • Verified agents

    Signed agent requests are recognised, not challenged.

  • CDN and firewall rules

    Stops scrapers without blocking AI answers.

Questions

What technical teams ask us first. Something else on your mind? Ask us on the strategy call.

What is technical SEO for AI agents?

It is the work that lets search engines, AI crawlers and AI agents reach, read and use your site: server rendering, Markdown for agents, structured data, bot policy and protocols like MCP and WebMCP. MaximusLabs audits all of it, builds the fixes or briefs your team, and measures every agent visit.

Do AI crawlers run JavaScript?

The major AI crawlers fetch your raw HTML and do not run JavaScript; a 2024 Vercel and MERJ study found none of them rendered it, while Google’s Gemini uses Googlebot, which does. MaximusLabs server-renders the pages that matter so every crawler sees the same content.

Is serving Markdown to AI agents cloaking?

Not when both formats carry the same content. Cloaking means showing bots different content to manipulate results. MaximusLabs serves the same facts as Markdown on the same URL, with Vary: Accept and a canonical, and checks parity on every release.

What is llms.txt, and does it help?

llms.txt is a proposed file, from September 2024, that maps your key pages for AI tools. No major AI engine has confirmed using it, and Google says Search ignores it. MaximusLabs ships it because it is cheap and helps agents, then measures whether anyone fetches it.

What are MCP, WebMCP and A2A, and do we need them?

MCP lets AI assistants call your tools and data, WebMCP (a proposed standard now in a Chrome origin trial) lets your pages expose actions to browser agents, and A2A lets agents discover and work with each other. MaximusLabs recommends them only where an agent has a real job to do on your site.

Should we block AI training crawlers?

That is a business choice. Blocking training crawlers such as GPTBot and ClaudeBot does not block the search and answer crawlers such as OAI-SearchBot, Claude-SearchBot and PerplexityBot. MaximusLabs sets a policy per purpose, so you can opt out of training and still be cited.

How is this different from MaximusLabs’ B2B SEO service?

Technical SEO makes the site readable and usable by search engines, AI crawlers and agents. B2B SEO decides what to rank for and writes the pages that win buyers. Most MaximusLabs clients fix the foundation first.

Who builds the fixes: MaximusLabs or our developers?

Both, depending on the format you choose. MaximusLabs either builds and ships the fixes itself, or specs each one for your developers and reviews the work, then re-checks every fix either way.
